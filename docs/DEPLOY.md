# Deploying VaultFlow on Cloudflare Pages

VaultFlow builds as a multi-page static website (`/` landing page, `/pricing/`, `/privacy/`, `/terms/`, `/refunds/`, `/cancel/<service-id>/`) plus the installable React app at `/app/` and optional Cloudflare Pages Functions under `functions/api/license/*` for Polar license proxy fallback.

## 1. Cloudflare Pages Project Settings

Connect your Git repository in **Cloudflare Dashboard → Workers & Pages → Create → Pages → Connect to Git** and configure:

| Setting | Value |
| --- | --- |
| **Framework preset** | None (Vite) |
| **Build command** | `npm run build` |
| **Build output directory** | `dist` |
| **Root directory** | `/` (default) |
| **Node.js version** | `22` (set `NODE_VERSION=22` in Environment Variables) |

Cloudflare automatically picks up:
- `public/_redirects` (copied to `dist/_redirects`) for `/app/* /app/index.html 200`
- `public/_headers` (generated by `scripts/generate-pages.ts` and copied to `dist/_headers`) for strict CSP and security headers
- `functions/api/license/*.ts` for `/api/license/validate`, `/api/license/activate`, and `/api/license/deactivate`

## 2. Environment Variables

Set these under **Settings → Environment variables** for **Production** (and optionally **Preview**). All `VITE_*` variables are public client configuration — **never** place private API keys or webhook secrets in any `VITE_*` variable.

| Variable | Required | Example | Purpose |
| --- | --- | --- | --- |
| `NODE_VERSION` | Yes | `22` | Ensures Cloudflare builds with Node 22 |
| `SITE_URL` | Yes | `https://vaultflow.app` | Base URL for canonical tags, Open Graph URLs, `sitemap.xml`, and `robots.txt` |
| `VITE_LICENSE_PROVIDER` | Yes | `polar` | Must be `polar` in production (`dev` is stripped from production builds automatically) |
| `VITE_POLAR_ORG_ID` | Yes (for Pro) | `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` | Public Polar organization ID used by Polar Customer Portal license validation |
| `VITE_POLAR_CHECKOUT_YEARLY` | Yes (for Pro) | `https://buy.polar.sh/...` | HTTPS Polar checkout link for the $19/year plan |
| `VITE_POLAR_CHECKOUT_LIFETIME` | Yes (for Pro) | `https://buy.polar.sh/...` | HTTPS Polar checkout link for the $39 lifetime plan |
| `VITE_LAUNCH_PRICE` | No | `0` (`1` to show `$29` launch price) | Toggles the launch price badge in the Upgrade sheet |
| `VITE_MOR_NAME` | No | `Polar` | Reseller name shown in Upgrade sheet small print |
| `VITE_ANALYTICS_SRC` | No | `https://plausible.io/js/script.js` | Cookie-less analytics script URL (Plausible or Umami). Also automatically added to CSP `_headers` when both analytics vars are set |
| `VITE_ANALYTICS_DOMAIN` | No | `vaultflow.app` (or Umami website UUID) | Domain / site ID for cookie-less analytics. Script never loads unless both `VITE_ANALYTICS_SRC` and `VITE_ANALYTICS_DOMAIN` are set |

## 3. Custom Domain Setup

1. Open your Pages project in Cloudflare Dashboard → **Custom domains** → **Set up a custom domain**.
2. Enter your apex domain (e.g., `vaultflow.app`). If your DNS is already hosted on Cloudflare, Cloudflare creates the proxied `CNAME` record automatically.
3. Optional: Add `www.vaultflow.app` and create a Cloudflare Redirect Rule (301 Permanent Redirect) from `www.vaultflow.app/*` to `https://vaultflow.app/$1` so canonical URLs stay consistent.
4. Wait for the TLS certificate status to become **Active** (usually 1–5 minutes).
5. Verify **SSL/TLS → Overview** is set to **Full (strict)** and **Always Use HTTPS** is enabled.
6. Confirm `SITE_URL` matches your live custom domain (`https://vaultflow.app`) and trigger a fresh deployment so `sitemap.xml`, `robots.txt`, and canonical links point to it.

## 4. Pre-Launch Checklist

- [ ] **Replace legal placeholders**: Search and replace `[OWNER NAME]`, `[CONTACT EMAIL]`, `[COUNTRY]`, and `[MoR NAME]` across `src/marketing/pageTemplates.ts` and `src/features/vault/presentation/VaultSettingsView.tsx`, then rebuild.
- [ ] **Review screenshots**: Verify or replace `public/screens/1.png`, `public/screens/2.png`, and `public/screens/3.png` with your final preferred product captures, and inspect `public/og-image.png` (`1200×630`).
- [ ] **Verify catalog prices & cancel links**: Spot-check `src/features/catalog/domain/serviceCatalog.ts` prices and official `cancelUrl` destinations, and add `lastChecked: 'YYYY-MM-DD'` dates as you verify them.
- [ ] **Test live Pro checkout & license key flow**: Complete a real checkout (or Polar sandbox checkout), paste the issued license key into `/app/#settings`, confirm activation, and test `/api/license/validate` proxy fallback.
- [ ] **Confirm zero dev artifacts in production**: Confirm `dist/` contains no `DEV-PRO` strings and `VITE_LICENSE_PROVIDER=polar`.
- [ ] **Verify routing & headers on live domain**:
  - `/` renders landing page without loading React
  - `/app/#calendar` opens directly on the Calendar tab
  - Refreshing `/app/` or `/app/anything` returns HTTP `200`
  - `/pricing/`, `/privacy/`, `/terms/`, `/refunds/`, `/cancel/netflix/`, `/sitemap.xml`, `/robots.txt` return HTTP `200`
  - Response headers include `Content-Security-Policy`, `Referrer-Policy`, `X-Content-Type-Options`, and `Permissions-Policy`
- [ ] **Run Lighthouse audit**: Run Lighthouse (Mobile + Desktop) against `/` and `/pricing/` and confirm 95+ across Performance, Accessibility, Best Practices, and SEO.
- [ ] **Submit sitemap**: Submit `https://<your-domain>/sitemap.xml` in Google Search Console and Bing Webmaster Tools.
